# Week 5 · observation

## Task 1 · PageRank, 그리고 망가지는 두 가지

**dead end 의 rank 는 고치기 전에는 그래프 밖으로 사라지고, 나는 모든 노드에 1/n 씩 나눠
보낸다.** 링크가 없는 열이 0 이라 받은 rank 를 넘기지 못하고, 매 반복 새어 나가 합이 0 이 된다
(검증에서 0.0000). 다른 선택지는 dead end 를 재귀적으로 지우고 나중에 순위를 매기는 것(§5.1.3)
인데, 그건 순위를 매기는 그래프 자체를 바꾼다. 균등 분배는 그래프를 그대로 두고 총합을 정확히
1 로 지키며, Task 3 의 dense 기준과 같은 규칙이라 두 과제가 같은 질문에 답한다.

**같은 수리가 둘 다 고치는 이유: 두 문제 모두 "surfer 가 빠져나갈 길이 없는 곳" 이고, 텔레포트는
어디서든 모든 노드로 가는 길을 만들어 준다.** dead end 에서는 갈 곳이 없어 rank 가 사라지고,
트랩에서는 나갈 곳이 없어 rank 가 쌓인다. 고친 뒤 트랩 C+D 는 1.0000 에서 0.8931 로 내려가고
A, B 가 0.0375, 0.0694 를 지킨다.

**β 는 surfer 가 다음 걸음에서 링크를 따라갈 확률이다.** 나머지 1 − β 의 확률로는 링크를 무시하고
주소창에 아무 페이지나 쳐서 이동한다. β = 0.85 면 평균 β/(1−β) ≈ 5.7번 링크를 따라간 뒤 한 번
새로 시작하는 셈이다.

## Task 2 · 수렴

**β → 1 에서 반복 수는 늘지만 조금이다: 14 → 24.** 돌리기 전에는 βᵏ 로 β = 0.99 에 2,291회가
필요하다고 예측했는데 틀렸다. 조기 종료 없이 5,000회 돌린 답과의 차이가 2e-11 이하라 가짜
수렴도 아니다. 실제 수렴 속도를 재 보니 **β × 0.27** 이었다 — βᵏ 는 상한이고, 이 그래프는 링크
구조가 빨리 섞여서(두 번째 고유값 약 0.27) β 의 영향이 0.27β 의 로그로만 들어온다.

**A4: 1,200 → 20,000 노드에서 반복 수는 그대로(+0 ~ +1), 시간은 약 20배.** 반복 수는 오차가
반복마다 얼마나 줄어드느냐, 즉 그래프의 모양으로 정해지고 크기와는 무관하다. 반복 한 번은
모든 간선을 한 번씩 도는 일이라 시간은 간선 수(17.3배)에 비례한다.

**A6: 상위 10위는 모든 β 에서 같은 집합이고, 순서는 β = 0.5 에서 처음 바뀐다(7·8위 교체).**
다만 상위 10개가 링크를 압도적으로 많이 받는 씨앗 노드들이라 안정적인 것이다. 발표된 순위를
믿을 때는 맨 위는 β 에 둔감하지만, 비슷비슷한 페이지가 다투는 중간 순위는 누군가 고른 0.85 에
기대고 있을 수 있다는 점을 염두에 둬야 한다.

## Task 3 · 행렬 없이

**M 대신 순위 벡터 두 개와 인접 리스트를 들고 있다: 부동소수 2n + 3 = 2,403개.** 인접 리스트는
노드 번호(정수) e = 5,877개라 부동소수가 아니다. dense 의 n² = 1,440,000 개 대비 **599배** 적고,
**81배** 빠르다(strong). 각 반복은 간선 e 개를 한 번씩 따라가며 "w 는 r[v]/outdeg(v) 를 받는다"
를 그대로 적용한다.

**R5 — 텔레포트는 모든 노드를 건드리지만 모든 노드에 같은 값을 준다.** 그래서 n×n 블록이 아니라
숫자 하나다. 모든 노드가 (1−β)/n 을 받고, dead end 의 몫도 β × (dead end 들의 rank 합)/n 으로
모두 같다. 이 둘을 반복마다 한 번 계산한 `base` 로 새 벡터를 채우고 시작하면 끝이다. 행렬로 쓰면
모든 칸이 같은 값인 덩어리가 곱셈에서는 스칼라 하나를 더하는 일이 된다(§5.2.3).

**dense 답과의 최대 차이는 1.18e-15 다.** 0 이 아닌 건 버그가 아니라 더하는 순서 때문이다. dense
는 행마다 j 순서로 곱해 더하고, 나는 간선을 따라 밀어 넣는다. 부동소수 덧셈은 결합법칙이 정확히
성립하지 않아 순서가 다르면 마지막 자리가 달라진다. 반복 횟수는 둘 다 20회로 같다.
