# Week 5 · observation

## Task 1 · PageRank, 그리고 망가지는 두 가지

**고치기 전 dead end 의 rank 는 그래프 밖으로 사라지고, 나는 모든 노드에 1/n 씩 나눠 보낸다.** 고치기
전에는 dead end 그래프의 합이 0.0000 이 됐다. 균등 분배를 고른 이유는 그래프를 바꾸지 않고 합을 1 로
지키며, Task 3 의 dense 기준과 같은 규칙이기 때문이다 (dead end 를 지우는 방법은 그래프가 바뀐다).

**같은 수리가 둘 다 고치는 이유:** 둘 다 surfer 가 빠져나갈 길이 없는 곳이고, 텔레포트가 어디서든 모든
노드로 가는 길을 만든다. 고친 뒤 트랩 C+D 는 1.0000 에서 0.8931 로 내려가고 A, B 가 0.0375, 0.0694 를
지킨다.

**β 는 surfer 가 링크를 따라갈 확률이고, 1 − β 의 확률로는 아무 페이지로나 순간이동한다.** β = 0.85 면
평균 β/(1−β) ≈ 5.7번 링크를 따라간 뒤 새로 시작한다.

## Task 2 · 수렴

**β → 1 에서 반복 수는 14 → 24 로 조금만 는다.** βᵏ 로는 β = 0.99 에 2,291회가 필요하다고 예측했는데
틀렸다. 실제 수렴 속도를 재 보니 다섯 β 모두 β × 0.27 이었다 — 이 그래프는 링크 구조가 빨리 섞여서
βᵏ 가 상한일 뿐이다. 5,000회 돌린 답과 차이가 2e-11 이하라 진짜 수렴이다 (`task2_why.py`).

**A4: 1,200 → 20,000 노드에서 반복 수는 그대로(+0 ~ +1), 시간은 약 20배.** 반복 수는 그래프의
섞이는 속도(모양)로 정해지고, 반복 한 번의 시간은 간선 수(17.3배)에 비례하기 때문이다.

**A6: 상위 10위는 모든 β 에서 같은 집합이고, β = 0.5 에서만 7·8위가 바뀐다.** 맨 위는 β 에 둔감하지만,
링크 수가 비슷한 페이지끼리 다투는 중간 순위는 누군가 고른 0.85 에 기댈 수 있다.

## Task 3 · 행렬 없이

**M 대신 순위 벡터 두 개(2n 개의 부동소수)와 인접 리스트(간선 e 개, 정수)를 둔다.** 부동소수는
2n + 3 = 2,403개로 dense 의 n² = 1,440,000개보다 599배 적고, 81배 빠르다(strong, `out/bench.txt`).

**R5 — 텔레포트는 모든 노드에 같은 값을 주므로 숫자 하나로 충분하다.** 모든 노드가 (1−β)/n 을 받고,
dead end 몫도 β × (dead end rank 합)/n 으로 모두 같다. 이 둘을 반복마다 한 번 계산해 새 벡터의 시작값으로
쓰면, 행렬에서 n×n 칸이던 것이 스칼라 덧셈 하나가 된다.

**dense 답과의 최대 차이는 1.18e-15 다.** 버그가 아니라 더하는 순서 차이다 — dense 는 행마다 j 순서로
더하고 나는 간선을 따라 밀어 넣는데, 부동소수 덧셈은 순서가 다르면 마지막 자리가 달라진다. 반복
횟수는 둘 다 20회다.
